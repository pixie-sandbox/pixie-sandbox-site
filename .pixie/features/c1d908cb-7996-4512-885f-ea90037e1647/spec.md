## Outcome

Users can return to the top of long pages with a single, smooth action via a footer-based icon.

## What was asked for

Add an icon-based 'back to top' control within the existing sandbox site footer. The control should only become visible once a user has begun scrolling on a page that is long enough to require scrolling. When activated, the control will perform a smooth scroll back to the top of the page. The control must be accessible via keyboard navigation and provide clear context to screen-reader users via an aria-label.

## Acceptance criteria

- **AC1** — given A page that is shorter than the viewport height, when The user views the page, then The 'back to top' control is not present in the DOM or is hidden from view.
- **AC2** — given A page that is taller than the viewport height, when The user has not yet scrolled, then The 'back to top' control is not visible.
- **AC3** — given A page that is taller than the viewport height, when The user scrolls down the page, then The 'back to top' control becomes visible in the footer.
- **AC4** — given The 'back to top' control is visible, when The user clicks the icon or presses Enter/Space while focused, then The page performs a smooth scroll animation to the top (y=0).
- **AC5** — given A screen reader is active, when The user navigates to the control, then The device announces 'Back to top' (via aria-label).
- **AC6** — given The code is being committed, when The build/linting process runs, then The build must pass with no linting errors or warnings.

## Components the Architect expected to change

- `components/Footer.tsx` (modify) — Update Footer to include the 'Back to top' control. Since visibility depends on scroll state, this component (or a sub-component within it) must become a client component.
- `components/BackToTop.tsx` (new) — New client component responsible for listening to scroll events, managing visibility state (based on scroll position and page height), and handling the smooth scroll to top.
