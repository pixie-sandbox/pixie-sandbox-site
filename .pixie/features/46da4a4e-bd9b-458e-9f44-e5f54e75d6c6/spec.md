## What was asked for

Implement a theme switching mechanism (Light/Dark mode) for the Pixie sandbox Next.js site. The system must detect the user's operating system preference on the initial visit, allow users to manually toggle between light and dark modes, and persist that preference across sessions and page refreshes using local storage. To ensure a high-quality user experience, the implementation must prevent the 'flash of unstyled content' (FOUC) where the wrong theme is visible during page load.

## Acceptance criteria

- **AC1** — given A user visits the site for the first time with their OS set to Dark Mode, when The page loads, then The site displays in Dark Mode without a visible flash of Light Mode.
- **AC2** — given A user has previously selected 'Light Mode', when The user refreshes the page or navigates to a new route, then The site remains in Light Mode.
- **AC3** — given The user is on any page of the site, when The user clicks the theme toggle, then The theme switches immediately and the new preference is saved.

## Components the Architect expected to change

- `components/ThemeToggle.tsx` (new) — A client-side component providing the UI (Sun/Moon icons) to toggle between light and dark modes.
- `components/ThemeProvider.tsx` (new) — A React Context provider to manage the current theme state and provide a toggle function to the UI.
- `app/layout.tsx` (modify) — Wrap the application in the ThemeProvider and inject a blocking `<script>` in the `<head>` to prevent FOUC by applying the correct class to `<html>` before render.
- `app/globals.css` (modify) — Ensure Tailwind's dark mode strategy is explicitly set to 'class' if not already configured, and verify existing CSS variables respond to the `.dark` class.
