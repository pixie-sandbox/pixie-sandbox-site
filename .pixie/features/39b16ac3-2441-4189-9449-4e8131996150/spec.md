## Outcome

Readers can narrow the changelog to a single year using a keyboard-accessible dropdown above the entry list, and the entry count reflects what they are seeing.

## What was asked for

The changelog page currently lists every entry in one long scroll. A reader looking for when something shipped has no way to narrow the view. This change adds a year filter above the entry list: a native `<select>` control with a visible 'Year:' label and an 'All years' default option. The option list is derived from the entries themselves, newest year first, so it never offers a year with no entries and picks up new years automatically as they are added. Selecting a year filters the list in place — no navigation, no URL change, purely client-side component state. The entry count beneath the heading reflects what is currently visible: 'All years' shows the total, and a selected year shows the count for that year.

## Acceptance criteria

- **AC1** — given the changelog page has been rendered, when a reader looks above the entry list, then a `<select>` control labelled 'Year:' is visible, has accessible name 'Filter entries by year', and its selected option is 'All years'
- **AC2** — given the changelog data contains entries in the years 2024, 2025 and 2026, when the year filter is rendered, then its options are exactly 'All years', '2026', '2025', '2024' in that order
- **AC3** — given the changelog data contains multiple entries in the same year, when the year filter is rendered, then that year appears exactly once in the option list
- **AC4** — given the changelog data is later extended with an entry in a year not previously represented, when the year filter is rendered against the updated data, then the new year appears in the option list with no code change to the filter component
- **AC5** — given the year filter is showing 'All years', when the reader selects a specific year, then only entries whose date falls in that year are visible, in newest-first order, and the URL is unchanged
- **AC6** — given the year filter is showing a specific year, when the reader selects 'All years', then every entry in the changelog is visible again in newest-first order
- **AC7** — given a year with exactly one entry is selected, when the entry count line is read, then it reads '1 entry'
- **AC8** — given a year with more than one entry is selected, when the entry count line is read, then it reads 'N entries' where N is the count of visible entries for that year
- **AC9** — given 'All years' is selected, when the entry count line is read, then it reads the total number of entries in the changelog using the existing singular/plural wording
- **AC10** — given the changelog data is empty, when the page is rendered, then the filter shows only the 'All years' option, the entry count reads '0 entries', and the entry list is empty
- **AC11** — given keyboard focus is on the year filter, when the reader changes the selection using the keyboard alone, then the visible entry list and the entry count update to match, with no mouse interaction required
- **AC12** — given an absolute date is shown for a visible entry, when the reader reads that date, then it is formatted as 'DD MMM YYYY' (for example '29 Aug 2026')
