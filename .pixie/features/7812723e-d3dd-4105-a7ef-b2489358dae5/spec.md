# Pixie provenance

Feature `7812723e-d3dd-4105-a7ef-b2489358dae5`. Generated by Pixie's agent chain — this file records *why* the accompanying code changed.

## Outcome

Every page of the sandbox site shows when the changelog was last updated, directly below the copyright line in the footer.

## What was asked for

Add a 'Last updated' timestamp row to the site-wide footer. The row appears on its own line beneath the existing copyright year, left-aligned to match it. The date is derived from the most recent entry in data/changelog.json and formatted as 'Last updated: DD MMM YYYY'. When the changelog contains no entries the row is omitted entirely — no fallback text is shown.

## Acceptance criteria

- **AC1** — given data/changelog.json contains at least one entry, and the most recent entry has date '2026-08-29T00:00:00.000Z', when the footer renders, then the footer contains the text 'Last updated: 29 Aug 2026'
- **AC2** — given data/changelog.json contains multiple entries with different dates, where '2026-08-29T00:00:00.000Z' is the most recent and '2026-01-15T00:00:00.000Z' is an older entry, when the footer renders, then the footer shows '29 Aug 2026' and does not show '15 Jan 2026'
- **AC3** — given data/changelog.json contains no entries, when the footer renders, then no text matching 'Last updated' is present in the footer
- **AC4** — given data/changelog.json contains at least one entry, when the footer renders, then the timestamp row is inside the footer landmark (role='contentinfo') and appears on its own row beneath the copyright year

## Where this was expected to land

- `components/Footer.tsx` — Add the timestamp row: import changelog data, find the most recent date, format it, and render conditionally.
- `__tests__/Footer.test.tsx` — Existing Footer test file. AC1–AC4 tests belong here (or alongside it — see open_questions).
