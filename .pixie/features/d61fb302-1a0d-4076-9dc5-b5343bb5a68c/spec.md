## Outcome

Readers can find a changelog entry by typing part of its title into a search box above the list, alone or combined with the existing year filter, and are told plainly when nothing matches.

## What was asked for

The changelog page at /changelog already offers a year filter above the entries list (via YearFilter, held by ChangelogFilteredList). This change adds a text search input on the same row as the year filter. The input narrows the visible entries as the user types by matching (case-insensitive, substring) against the entry title only. Search and the year filter combine as AND — both must match for an entry to be shown. When the input has any text, a clear (×) button appears inside it; clicking it wipes the search value. When the combined filters match no entries, both controls remain on screen and a plain-text line 'No entries match.' is rendered where the entries list would be.

## Acceptance criteria

- **AC1** — given the changelog page is loaded with at least one entry, when the page renders, then a text input with accessible name 'Search' and the existing year-filter control both appear above the entries list on the same row
- **AC2** — given entries include titles 'Added dark mode', 'Improved DARK theme contrast' and 'Fixed login bug', when the user types 'dark' into the search input, then 'Added dark mode' and 'Improved DARK theme contrast' are shown and 'Fixed login bug' is not — proving both substring (not prefix) and case-insensitive matching
- **AC3** — given the user has typed 'dark' (lowercase) into the search input and entries include the mixed-case title 'Improved DARK theme contrast', when the filter applies, then 'Improved DARK theme contrast' is visible (case-insensitive match confirmed against an input where a case-sensitive implementation would disagree)
- **AC4** — given entries include {title: 'Added dark mode', date: '2026-09-01'}, {title: 'Improved DARK theme contrast', date: '2025-05-01'} and {title: 'Fixed login bug', date: '2026-08-01'}, when the user selects year '2026' in the year filter and types 'dark' in the search input, then only 'Added dark mode' is shown — 'Improved DARK theme contrast' is excluded by the year, 'Fixed login bug' by the search
- **AC5** — given the changelog page is loaded, when the user types 'zzzqqq' into the search input (no entry title contains it), then the search input and the year filter both remain visible, and the text 'No entries match.' is rendered in place of the entries list; no entry cards are shown
- **AC6** — given the search input is empty, when the page renders, then no button with accessible name 'Clear search' is present in the DOM
- **AC7** — given the user has typed 'dark' into the search input so a button with accessible name 'Clear search' has appeared, when the user clicks that button, then the search input's value is empty, the clear-search button is no longer present, and entries excluded only by the search text (e.g. 'Fixed login bug') are visible again
- **AC8** — given the user types '   ' (whitespace only) into the search input, when the filter applies, then all entries the year filter alone would show are shown (whitespace-only input is treated as empty)
