Feature `91a1396b-24fe-4091-9f48-2133bbd6ae34`. Generated by Pixie's agent chain — this file records *why* the accompanying code changed.

## Outcome

A reader who pastes a long search into the changelog can no longer share a URL that carries more text than the page will use; the URL always matches what the page reads back.

## What was asked for

The changelog page has a title search whose value is mirrored into the URL as ?q=. When a link is opened the read path caps ?q= at 200 characters, so the input, the filter and the URL all agree on at most 200 characters of search. The write path has no matching cap: while a reader types or pastes into the search input, whatever they enter is written to the URL verbatim, so a paste of 5000 characters produces a shareable link with a 5000-character ?q=. Any reader who opens that link still only sees the first 200 characters — the tail is data that travels with the link and is never used. Security review on PR #22 flagged this. The fix applies the same 200-character cap on the write path so the URL never carries more than the page will read back. The search input itself is deliberately left alone: the reader continues to see what they typed or pasted, and only the URL is trimmed.

## Acceptance criteria

- **AC1** — given the changelog page is rendered with entries and an empty search input, when the reader clears the search input after typing into it, then the URL no longer carries a ?q= parameter
- **AC2** — given the changelog page is rendered with entries, when the reader types a search value under 200 characters (for example 'release notes'), then the URL's ?q= parameter carries the whole value verbatim
- **AC3** — given the changelog page is rendered with entries, when the reader enters a search value of exactly 200 characters, then the URL's ?q= parameter carries all 200 characters unchanged
- **AC4** — given the changelog page is rendered with entries, when the reader enters a search value of 201 characters, then the URL's ?q= parameter carries only the first 200 characters and drops the 201st
- **AC5** — given the changelog page is rendered with entries, when the reader pastes a search value of 500 characters, then the URL's ?q= parameter carries only the first 200 characters AND the search input continues to display the full 500-character string
