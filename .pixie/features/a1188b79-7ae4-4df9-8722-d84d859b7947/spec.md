## Outcome

A reader who has narrowed the changelog to a year, a search term, or both can share the URL and have the recipient see the same view — and can refresh the page without losing the filter.

## What was asked for

The changelog's year filter and title search currently live in component state only: a reader who has narrowed the list has a view they cannot share (a link goes to the unfiltered list), and a page reload discards the narrowing. This change moves both filters into the URL query string under `?year=` and `?q=`, so a filtered view is shareable, bookmarkable, and reload-safe. The URL is the source of truth on load; user interaction with either filter updates the URL using replace (not push) so the browser Back button leaves `/changelog` rather than stepping through every keystroke or year change. An absent, empty (`?q=`), or whitespace-only parameter means 'no filter'. An unknown `?year` value (non-numeric, or numeric with no matching entry) is ignored — the full list renders — rather than an empty list. Both parameters combine when both are present. The RSS feed at `/changelog.xml` is not affected by these parameters.

## Acceptance criteria

- **AC1** — given a changelog dataset containing at least one 2024 entry and at least one 2025 entry, when a visitor opens /changelog?year=2024, then the year filter control shows 2024 on load, only 2024 entries render, and the on-page count reflects the filtered number
- **AC2** — given an entry titled 'Firebase logon shipped' and entries whose titles do not contain 'firebase', when a visitor opens /changelog?q=FIREBASE, then the search input shows 'FIREBASE' on load, the Firebase entry renders, and non-matching entries do not
- **AC3** — given entries in multiple years and with varying titles, when a visitor opens /changelog?year=2025&q=retry, then only entries that are from 2025 AND whose titles contain 'retry' render; entries matching only one of the two do not
- **AC4** — given a changelog with entries in multiple years, when a visitor opens /changelog?q=, then all entries render, identical to opening /changelog with no query string
- **AC5** — given a changelog with entries in multiple years, when a visitor opens /changelog?q=%20%20%20, then all entries render (whitespace-only is treated as no filter)
- **AC6** — given a changelog with entries in 2024 and 2025, when a visitor opens /changelog?year=notayear, then all entries render (non-numeric year is ignored), rather than an empty list
- **AC7** — given a changelog whose oldest entry is from 2024, when a visitor opens /changelog?year=1999, then all entries render (unknown numeric year is ignored), rather than an empty list
- **AC8** — given a visitor viewing /changelog with no query string, when the visitor selects year 2025 from the year filter, then the URL becomes /changelog?year=2025 via history replace (not push), and the browser back-navigation entry is unchanged
- **AC9** — given a visitor viewing /changelog with no query string, when the visitor types 'firebase' into the search input, one character at a time, then the URL updates to /changelog?q=firebase using history replace on each keystroke, and no additional history entries are pushed
- **AC10** — given a visitor viewing /changelog?year=2025, when the visitor clears the year filter (selects the 'all years' option), then the URL becomes /changelog with no query string; it does not become /changelog?year=
- **AC11** — given a visitor viewing /changelog?q=firebase, when the visitor deletes the search input's contents, then the URL becomes /changelog with no query string; it does not become /changelog?q=
- **AC12** — given a visitor viewing /changelog with a q= value that matches no entries, when the filter is applied, then an empty result region is rendered (not the full unfiltered list, and not a raw whitespace gap); the count indicator shows zero
- **AC13** — given the changelog dataset, when a request is made to /changelog.xml with or without any query string, then the RSS body is identical to the body served before this change and identical whether ?year or ?q are present
