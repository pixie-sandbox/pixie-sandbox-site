## Outcome

A reader who narrows the changelog by year or title can share or bookmark the URL and the recipient sees the same filtered view; reloading preserves it.

## What was asked for

The changelog page shows a list of entries with two filters — a year dropdown and a title search — whose state lives in `ChangelogFilteredList` via `useState`. A reader who has narrowed the list cannot share that view: the URL does not change as they filter, so pasting the address into a message shows the recipient the unfiltered page, and reloading loses the narrowed view. This change lifts both filters into the URL query string (`?year=` and `?q=`) and reads them back on mount, so a filtered view is shareable and survives reload. Filter changes use `router.replace`, not `router.push`, so Back leaves the changelog rather than walking through every keystroke. Absent, empty and whitespace-only parameters all mean no filter; an unknown or malformed year is silently ignored; and a very long `q` is bounded at 200 characters and filtered on the truncated value so a shared link cannot carry an unbounded string into the input.

## Acceptance criteria

- **AC1** — given a visitor opens /changelog with no query parameters, when the page renders, then the year filter shows no selection (default option), the search input is empty, and the entry list contains every entry from data/changelog.json
- **AC2** — given a visitor opens /changelog?year=2026 and 2026 is a year present in the entries, when the page renders, then the year filter shows 2026 selected and the entry list contains only entries whose date falls in 2026
- **AC3** — given a visitor opens /changelog?q=dark and at least one entry has 'dark' in its title (case-insensitive), when the page renders, then the search input contains 'dark' and the entry list contains only entries whose title matches 'dark' as a case-insensitive substring
- **AC4** — given a visitor opens /changelog?year=2026&q=dark, when the page renders, then the entry list contains only entries that are both from 2026 AND whose title matches 'dark' case-insensitively
- **AC5** — given a visitor opens /changelog?year=9999 and no entry has a 2026 or later date matching 9999, when the page renders, then the year filter shows no selection and the entry list contains every entry, as if the year parameter had been absent
- **AC6** — given a visitor opens /changelog?q=, when the page renders, then the search input is empty and the entry list contains every entry, as if the q parameter had been absent
- **AC7** — given a visitor opens /changelog?q=%20%20%20, when the page renders, then the search input contains the whitespace (as sent) OR is empty, but the entry list contains every entry, treating the query as no filter after trimming
- **AC8** — given a visitor opens /changelog?year=abc, when the page renders, then the year filter shows no selection and the entry list contains every entry, as if the year parameter had been absent
- **AC9** — given a visitor is on /changelog with no filters applied, when they select 2026 from the year filter, then the URL becomes /changelog?year=2026 via history replacement (window.history length does not increase) and the entry list updates to 2026 entries only
- **AC10** — given a visitor is on /changelog with no filters applied, when they type 'firebase' into the search input one character at a time, then each keystroke updates the URL via history replacement so window.history length is unchanged from before typing began, and after all keystrokes the URL query is ?q=firebase
- **AC11** — given a visitor navigated to /changelog from another page and has since selected a year and typed a search, when they press the browser Back button, then the browser leaves /changelog for the previous page rather than stepping through prior filter states
- **AC12** — given a visitor is on /changelog?year=2026&q=firebase with the filtered list showing, when they reload the page, then the year filter shows 2026, the search input contains 'firebase', and the entry list shows the same filtered set as before the reload
- **AC13** — given a visitor opens /changelog?q=dark, when the page renders, then document.activeElement is not the search input and not the year filter — page load does not steal focus into either control
- **AC14** — given a visitor opens /changelog?q=<a string of 500 characters, where the first 200 characters would match at least one entry title and the remainder would not>, when the page renders, then the search input value is exactly the first 200 characters of the parameter (input.value.length === 200), and the entry list is filtered by case-insensitive substring match on that 200-character prefix — not the full 500-character string
