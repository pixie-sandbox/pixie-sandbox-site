## Outcome

Users who encounter a broken link are greeted with a branded, accessible error page that provides a clear path back to the homepage.

## What was asked for

Implementation of a custom 404 error page for the Pixie sandbox site to replace the default framework error. The page will feature a professional, helpful tone, a centered 'hero' layout, and a single primary action button to return the user to the homepage. The page must be fully responsive, support both light and dark themes via the existing site theme state, and meet accessibility standards for keyboard and screen-reader users.

## Acceptance criteria

- **AC1** — given A user enters a URL that does not exist on the sandbox site, when The page loads, then They see a custom 404 page with a 'Page not found' heading and a helpful explanation instead of the framework default.
- **AC2** — given The user is on the custom 404 page, when They click the 'Return to Home' button, then They are redirected to the site's root URL.
- **AC3** — given The site is in dark mode, when The 404 page is viewed, then The background and text colors match the established dark theme palette.
- **AC4** — given A screen-reader user visits the 404 page, when The page loads, then The 'Page not found' h1 is the first meaningful element announced.

## Components the Architect expected to change

- `app/not-found.tsx` (new) — Next.js special file to intercept 404 errors. It will use the site's standard layout by virtue of being in the app directory, but we must ensure it fits the design.
