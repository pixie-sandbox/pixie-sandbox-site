## Outcome

Users encounter a branded, accessible error page instead of a broken framework default when they navigate to a non-existent URL.

## What was asked for

Replace the default Next.js framework 404 error page with a custom, branded 404 page for the Pixie sandbox site. The page will provide clear, plain-language feedback that the requested URL was not found and offer a single, primary call-to-action to return to the homepage. The page will be integrated into the existing site layout, including the global header and footer, and will support light/dark themes and accessibility standards.

## Acceptance criteria

- **AC1** — given A user enters a non-existent URL in the browser, when The page loads, then The user sees the custom error message and the 'Return to Home' button instead of the framework default.
- **AC2** — given The user is on the 404 page, when They click the 'Return to Home' button, then They are redirected to the site's homepage.
- **AC3** — given The user is navigating via keyboard, when They tab through the 404 page, then The focus moves predictably to the 'Return to Home' button and follows the header/footer structure.
- **AC4** — given The user has dark mode enabled in their system or site settings, when The 404 page is rendered, then The colors and contrast conform to the site's dark theme specification.

## Components the Architect expected to change

- `app/not-found.tsx` (new) — Creates the custom 404 error page with branded messaging, a 'Return to Home' link, and layout mirroring the homepage.
