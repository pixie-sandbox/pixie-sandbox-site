# Pixie provenance

Feature `697bbda1-0565-4949-b410-dec37782a356`. Generated by Pixie's agent chain — this file records *why* the accompanying code changed.

## Outcome

Visitors can view a fictional customer's three bank accounts and their recent transactions on the sandbox site, presented as a small internet-banking demo styled in deep blue.

## What was asked for

Turn the Pixie sandbox site into a small internet-banking demo for a fictional Australian bank, 'Northline Bank', styled to evoke a modern local internet-banking site (deep-blue primary palette, card-based accounts overview, clean typography) without reproducing any real bank's logos or trademarks. There is no sign-in; the site behaves as if a fictional customer, Alex Taylor, is signed in. The home page becomes an accounts overview showing three accounts — Everyday, Savings, and a Credit card — each with its name, a masked account number showing only the last four digits, and its balance in Australian dollars. Savings additionally shows an interest rate; Credit card shows the amount owing and the credit limit. Each account is a link to its own page at /accounts/<id>, which shows the account's details and a list of transactions newest first (date, description, signed amount, and running balance). The balance on the overview equals the balance after the newest transaction for each account. Unknown account ids fall through to the existing 404 page. Accounts and transactions come from a single data file at data/accounts.json, with about twelve realistic transactions per account. A simple header appears on every page linking to Accounts (home) and Changelog; the changelog page and its RSS feed keep working unchanged. There is no demo banner, no sign-in flow, and no transfer, payment or search functionality — those are explicitly out of scope.

## Acceptance criteria

- **AC1** — given a visitor is on the home page (/) after the change, when the page has rendered, then they see the greeting 'Hello, Alex' and exactly three account entries labelled 'Everyday', 'Savings' and 'Credit card'
- **AC2** — given a visitor is on the home page, when they look at each account entry, then each shows a masked account number that ends with a distinct four-digit sequence and does not contain any other digits of the account number
- **AC3** — given a visitor is on the home page, when they look at the Savings account entry, then they see the text '4.50% p.a.'
- **AC4** — given a visitor is on the home page, when they look at the Credit card account entry, then they see both an amount owing formatted in AUD (e.g. '$847.20') and a credit limit formatted in AUD (e.g. '$10,000.00'), each clearly labelled
- **AC5** — given a visitor is on the home page, when they inspect each account entry as an interactive link, then Everyday links to /accounts/everyday, Savings links to /accounts/savings, and Credit card links to /accounts/credit-card
- **AC6** — given a visitor opens /accounts/everyday, when the page has rendered, then they see 'Everyday' as the account name, the same masked number shown on the overview, and the same balance shown on the overview
- **AC7** — given a visitor is on /accounts/everyday, when they view the transactions section, then transactions appear in descending date order and each row shows a date in the form 'DD MMM YYYY', a description, a signed amount (positive prefixed '+', negative prefixed '-'), and the balance after that transaction in AUD
- **AC8** — given a visitor is viewing a transaction list, when they see a money-in row, then its amount starts with '+' and is rendered with a distinct colour (green); and when they see a money-out row, its amount starts with '-' and is rendered with the default text colour
- **AC9** — given the three accounts on the overview and their detail pages, when the overview balance is compared with the balance after the newest transaction on the corresponding detail page, then the two figures are equal for every account
- **AC10** — given a visitor opens /accounts/mystery (or any id not present in data/accounts.json), when the route resolves, then the existing not-found page (app/not-found.tsx) renders
- **AC11** — given a visitor is on the home page, an account detail page, /changelog, or the not-found page, when they inspect the top of the page, then they see 'Northline Bank' as a link to /, 'Accounts' as a link to /, and 'Changelog' as a link to /changelog
- **AC12** — given any rendered page that displays an account, when the DOM is inspected, then no run of six or more consecutive digits belonging to an account number appears anywhere in the DOM — only the last four digits are present
- **AC13** — given an account transaction has ISO date '2026-08-29', when it renders on the account detail page, then it displays as '29 Aug 2026'
- **AC14** — given the data file data/accounts.json is loaded, when counting transactions for each account, then each of the three accounts has between 10 and 15 transactions inclusive (target: ~12), all with plausible Australian merchant descriptions and ISO dates within the last three months
- **AC15** — given /changelog and /changelog.xml, when they are opened after the change, then entries render in the same order and format as before, and the RSS feed contains the same items with the same channel metadata
- **AC16** — given the site's source and public assets, when searched, then they contain no ANZ logo, wordmark, or reproduction of ANZ trademarked material; only a generic deep-blue palette is applied
- **AC17** — given app/globals.css after the change, when parsed, then it defines a primary-blue CSS variable used by header, links, and account-card accents in both light and dark modes

## Where this was expected to land

- `app/page.tsx` — Replace the Next.js starter with the accounts overview: greeting, three account cards, links to detail pages.
- `app/layout.tsx` — Mount the new Header component and set the site title metadata; preserve the anti-FOUC blocking script and ThemeProvider wrapping.
- `app/globals.css` — Add deep-blue primary palette CSS variables for light and dark modes.
- `app/accounts/[id]/page.tsx` — new file — Dynamic route for account detail (name, masked number, balance, transactions). Uses Next.js notFound() for unknown ids. New file per Next.js App Router convention.
- `data/accounts.json` — new file — Source of truth for accounts and transactions, mirroring the data/changelog.json pattern.
- `lib/accounts.ts` — new file — Typed loader and helpers for reading accounts data (getAccounts, getAccountById). Matches lib/readingTime.ts and lib/slugify.ts placement convention.
- `lib/formatMoney.ts` — new file — Format AUD amounts as $1,234.56 with signed prefix. Matches lib/ placement convention.
- `lib/formatDate.ts` — new file — Shared DD MMM YYYY formatter for transaction dates (DTS-04). Footer's local formatter is expected to be refactored to use it.
- `components/Header.tsx` — new file — New header component with site-name link, Accounts / Changelog nav, and ThemeToggle. Extracted from app/layout.tsx so it can be unit-tested and reused. Matches components/ placement convention.
- `components/AccountCard.tsx` — new file — One card on the accounts overview.
- `components/TransactionList.tsx` — new file — Transactions table/list on the account detail page.
- `components/Footer.tsx` — Refactor local formatDate to use the shared lib/formatDate.ts; rendered output unchanged.
- `__tests__/Home.accountsOverview.test.tsx` — new file — Acceptance test file for the home-page criteria that have an existing entry point (@/app/page).
