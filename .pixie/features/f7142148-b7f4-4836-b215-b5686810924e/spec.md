## Outcome

Users can see an estimated reading time next to each changelog entry to help them decide if they want to read the update.

## What was asked for

The Pixie sandbox changelog page will display an estimated reading time for each entry. This estimate is calculated on the client side based on the word count of the entry description, using a rate of 200 words per minute. The reading time will be rendered on the same line as the entry title, separated by a bullet character, using small, muted text. This change is strictly a UI enhancement and does not involve modifications to the underlying data source or the RSS feed.

## Acceptance criteria

- **AC1** — given A changelog entry with a description of 450 words, when The changelog page is viewed, then The system shall display '3 min read' next to the title on the same line.
- **AC2** — given A changelog entry with a description of 10 words, when The changelog page is viewed, then The system shall display '1 min read' next to the title on the same line.
- **AC3** — given A changelog entry with a description of 0 words, when The changelog page is viewed, then The system shall display '1 min read' next to the title on the same line.
- **AC4** — given The changelog page is rendered, when Inspecting the DOM, then The reading time text must be styled as small and muted (e.g., using Tailwind 'text-sm text-muted-foreground' or equivalent).

## Components the Architect expected to change

- `ChangelogEntry component` (modify) — Update the UI to include the reading time estimate next to the entry title.
- `Reading time helper` (new) — A utility function to calculate reading time based on word count (200 WPM) and handle rounding/minimums.
- `ChangelogEntry tests` (new) — Add unit tests for the reading time calculation logic and component rendering.
