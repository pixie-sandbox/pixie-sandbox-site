## Outcome

Visitors on the Northline Bank sandbox's banking pages see a thin strip at the top of the header saying "Signed in as Alex Taylor".

## What was asked for

Add a thin 'signed-in' strip to the top of the Northline Bank sandbox site's header that reads "Signed in as Alex Taylor". The site has no authentication and deliberately behaves as if the fictional customer Alex Taylor is always signed in (lib/accounts.ts); the strip makes that visible the way real internet banking does. The strip is rendered inside the existing site header (components/Header.tsx, the page's single banner landmark), above the existing row of site name, navigation and theme toggle, which stays exactly as it is. It appears only on the banking pages: the Accounts overview at / and the three valid account detail pages /accounts/everyday, /accounts/savings and /accounts/credit-card. It is hidden on /changelog, on not-found pages (including invalid account ids such as /accounts/mystery), and on every other path. It is fixed text with no sign-out control and no data loading.

## Acceptance criteria

- **AC1** — given a visitor on the Accounts overview at /, when the header renders, then the header (banner landmark) contains the text "Signed in as Alex Taylor", the header's text contains no digits, and the header contains no heading element
- **AC2** — given a visitor on /accounts/everyday, /accounts/savings or /accounts/credit-card, when the header renders, then the header contains the text "Signed in as Alex Taylor" on each of the three pages
- **AC3** — given a visitor who was on a banking page (where the strip shows), when they are on /changelog, then the header does not contain the text "Signed in as"
- **AC4** — given a visitor on /accounts/mystery, /accounts/EVERYDAY, /accounts, /accounts/everyday/extra or /no-such-page, when the header renders, then the header does not contain the text "Signed in as" on any of them, while the same header on /accounts/everyday does
- **AC5** — given a visitor on /, when the header renders, then there is exactly one banner landmark on the page, the "Signed in as" text is inside it, and it comes before the "Northline Bank" link in reading order
- **AC6** — given a visitor on / where the strip shows, when they look for a way to sign out, then the header has no link or button named sign out or log out, its links are exactly Northline Bank, Accounts and Changelog in that order, and its only button is the theme toggle
- **AC7** — given any page of the site, when the existing header, navigation, theme toggle, palette and changelog behaviour is exercised, then it behaves exactly as it did before — covered by the existing tests `e2e/banking.e2e.ts`, `__tests__/ThemeToggle.test.tsx`: keep them passing; no new test is needed
- **AC8** — given / and /accounts/credit-card at 375px wide, in both light and dark themes, when a person views the page, then the strip is a single line above the header row, the header row's site name, links and toggle sit where they did before the change, and nothing overlaps — a person checks this before merging: Open / and /accounts/credit-card in browser dev tools at 375px width, toggle the theme, and compare the header row against main; the strip must be one line and the row beneath it unchanged.; no test is needed
- **AC9** — given the strip in light theme and in dark theme, when its text colour is measured against its background, then the contrast ratio is at least 4.5:1 in both themes — a person checks this before merging: Use the browser's contrast checker (or the computed colours with a WCAG contrast calculator) on the strip text in each theme and record both ratios in the PR.; no test is needed
- **AC10** — given a visitor loading / with JavaScript disabled, when the page loads, then the strip is already visible in the server-rendered page, and with JavaScript enabled the page does not visibly jump when it finishes loading — a person checks this before merging: Load / with JavaScript disabled in dev tools and confirm the strip shows; re-enable JavaScript, hard-reload, and confirm the header does not shift.; no test is needed
