# Pixie provenance

Feature `a2cb7267-30f2-4fd9-8d54-74801b923726`. Generated by Pixie's agent chain — this file records *why* the accompanying code changed.

## Outcome

Readers can see how many entries each year has directly in the changelog's year filter, so a busy year and a quiet one are distinguishable without selecting them.

## What was asked for

The changelog's year filter currently lists years as bare numbers, so a reader cannot tell a busy year from a quiet one without selecting it. This change appends a per-year entry count to each option in the compact form `2026 (4)`, and appends the total to the default option in the form `All years (4)`. Counts are derived from the same `entries` array that drives the list below the filter, so the numbers in the options always agree with what selecting the year displays. The count sits inside the `<option>` text content itself, so a screen reader hears it as part of the option rather than as a separate element. The control's existing keyboard behaviour is unchanged — it remains a native `<select>` with its existing `<label>` association and `aria-label`. The existing count paragraph above the filter (which says how many entries are currently shown for the active selection) is unchanged: it answers a different question and is kept as-is.

## Acceptance criteria

- **AC1** — given a changelog with four entries all dated in 2026, when the changelog page renders, then the year filter contains an option whose text is `2026 (4)` and a default option whose text is `All years (4)`
- **AC2** — given a changelog with two entries in 2026 and one entry in 2025, when the changelog page renders, then the year filter contains an option whose text is `2026 (2)`, an option whose text is `2025 (1)`, and a default option whose text is `All years (3)`, with the year options in newest-first order
- **AC3** — given a changelog with exactly one entry in 2020, when the changelog page renders, then the year filter contains an option whose text is `2020 (1)` (no `entries` / `entry` word, no singular/plural handling)
- **AC4** — given a changelog with no entries, when the changelog page renders, then the year filter contains only the default option, whose text is `All years (0)`, and no year options
- **AC5** — given the year filter is rendered with any set of entries, when a user selects a year from the filter and the list re-renders, then the number in parentheses on the selected year's option equals the number of entries rendered in the list below
- **AC6** — given the year filter is rendered, when assistive technology reads a year option or the default option, then the accessible name of the option is the same string as its visible text (the count is part of the option's text content, not a sibling element or ARIA override)
- **AC7** — given the year filter is rendered, when the DOM is inspected, then the control is a native `<select id="year-filter">` with `aria-label="Filter entries by year"`, associated with a `<label htmlFor="year-filter">`, and each option is a native `<option>` element with no `aria-label`, `aria-describedby`, or nested markup
- **AC8** — given a changelog with two entries in 2026 and one entry in 2025, when the changelog page renders and no year has been selected, then the count paragraph above the `<select>` still reads `3 entries` (its existing behaviour is unchanged by this feature)
